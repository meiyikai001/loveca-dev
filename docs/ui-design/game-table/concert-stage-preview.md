# 三维舞台本地试作

> 文档类型：专题说明
> 当前状态：2026-10-05 概念图方向的首轮可操作样板已接入本地工作区；仅本地调试与对墙打显式启用，尚未作为正式联机桌面开放
> 维护范围：舞台渲染、原桌面交互衔接、动效与降级边界

## 入口和范围

在支持 WebGL2、视口至少 768 × 640 的本地调试或对墙打页面，点击右上角「舞台试作 · 2D」切换；再次点击恢复原桌面。选择按地址与端口保存在当前浏览器，5173 与独立演示页不共享开关。尺寸或显卡条件不满足时保留入口并说明原因。`?stage3d=1` / `?stage3d=0` 可指定初始选择，但不能绕过模式、尺寸或 WebGL 检查。手机、只读回放、观战、远程调试及正式联机继续使用原桌面。5173 正常入口可通过「对战 → 双人调试 → 选择双方卡组 → 开始」后启用；登录后的在线对墙打使用远端会话，当前仍保留二维，开关说明如何进入本机试作。

舞台使用 Three.js 与 React Three Fiber：有厚度的地板、灯架、音箱、远端灯带、观众光点、实体卡牌与接触阴影共用一个透视相机。场上成员、LIVE、成功 LIVE、能量及卡堆进入三维场景；成员、LIVE 与成功 LIVE 槽框和合法落点提示也在同一场景中渲染。手牌常驻展示仍是二维 DOM 扇形，拖起后可由共享三维卡接管；卡牌详情、选择菜单、数值和阶段按钮保留原交互。三维模式把对局控制面板收成可展开入口，以留出对手手牌空间。

本轮以固定机位与可操作性为基础，使用程序生成的场景几何与材质。后续舞台修订已加入两翼 LED 屏、具有扬声器单元的音箱、细发光芯与柔光的应援棒，以及身份面板、重新构图的手牌扇和右下阶段 HUD。按概念图的黑金、淡紫舞台方向重做，但不声称达到概念图的全部资产精度；当前玩家投影没有头像字段，身份圆标使用音乐徽记。角色三维模型、额外 LIVE 演出、音效、镜头切换和移动端三维适配不在本轮实现中；尚未完成跨 GPU 性能验收。

## 与现有桌面的关系

`GameBoard` 仍使用同一个 `PlayerArea`、store selector、玩家投影与命令路径。`Stage3dBoardHost` 只读取显式标记为场上表面的 DOM：已经允许展示的卡图、姿态、选中/能力提示和布局矩形。背面只采集卡背，渲染器不读取卡组内容、对手手牌或权威游戏状态。

DOM 仍提供区域中心的布局锚点；`geometry.ts` 统一产生卡牌和槽位的世界姿态、投影四边形及命中范围。场上牌尺寸不再从各自 DOM 包围矩形反算；成员和 LIVE 共用固定物理尺寸，横置仅改变明确的模型朝向。原 DOM 事件表面通过投影矩阵跟随实际卡面，拖放仍返回原 droppable ID，不能退回旧矩形接受场上落点。采样时同步撤销再恢复自己写入的矩阵，避免投影结果再次成为布局输入。

纹理确认加载后才隐藏对应 DOM 卡图，菜单与数值保留。纹理失败、卡牌离开场区、关闭舞台、切换布局及 WebGL context 丢失时释放投影与隐藏标记。显卡中断后显示原桌面和重试提示。

Three.js 场景通过动态 import 按需运行。普通桌面不创建 Canvas；现有 PWA 仍预缓存构建中的 JavaScript，不能据此保证非三维设备完全不下载场景包。

## 按需绘制与空闲负载

布局调整已保存为 `10e1dfd7`。其后的性能修订将 Canvas 改为 `frameloop="demand"`，保持原来的材质、分辨率和阴影质量。拖动开始／结束、异步纹理、卡牌与槽框更新主动唤醒绘制；拖牌代理和 VFX 集合只在仍有活动对象时续帧，最后一个动效结束或取消后停止。页面重新可见时补绘，动效继续沿原有绝对时间结算，不修改规则状态或表现时长。

DOM 仍是布局依据，但不再永久以 20 Hz 轮询。区域 DOM 变化、窗口尺寸／滚动、可见性、图片加载及有限 CSS 动画触发采样，变化期间最多每 50ms 采集一次，稳定后不保留轮询帧。投影样式写入期间断开 MutationObserver，避免观察自身写入造成循环；对齐偏移小于 0.05px 时不反复修正，消除浏览器约 0.008px 的布局取整振荡。

验证覆盖调度休眠／唤醒、隐藏与卸载、并发 VFX 和最后动效取消，以及原有几何、拖动、投影与布局回归。真实 `GameBoard` 在宽屏、1280 × 720、850 × 720 的稳定三秒采样中，WebGL 绘制、清屏及投影写入均为零；完成鼠标手牌拖入成员区、无效落点保留手牌、能量横置、专属登场、混合增益及减少动态检查。850 宽度下 18 个槽位命中正确；390 × 720 无三维 Canvas、无横向溢出。延迟纹理恢复投影，显卡中断后清除投影并恢复二维桌面。后台暂停／唤醒有调度单测覆盖；浏览器自动化可能激活被读取的标签，本次未据此声明独立后台性能测量。证据沿用本地试作目录的 `output/concept-revision/demand-render-checks.json` 与 `demand-gain-settled.jpg`。这些结果证明当前本机的空闲绘制行为，不代表跨 GPU 功耗基准。

## 已确认基线：概念图方向的可操作样板（373032be）

本节覆盖下方历史修订中的旧卡宽、厚度与构图参数。首轮先确认真实桌面中的构图、薄卡体与凸起边框；现阶段仍由 DOM 提供区域中心，不将这次样板描述为完整的世界布局重构。

成员和 LIVE 的印刷面宽度统一为 1.75 世界单位，长宽比保持 1.4。单卡纸芯厚度由短边的 6% 改为 1.7%，上下限为 0.003–0.04；边框在原完整卡图外侧增加约短边 2.2% 的窄金属边，具有真实的内外倒角和凸起截面。纸芯、深色覆膜与边框分别受光，环境反射提供暖金和冷紫的高光，避免通过加厚卡底表达实体感。静态卡、拖牌、普通移牌和专属落牌共用这一实体；压卡间距同时计入纸芯和凸起边框，回归检查上下实体之间保留空隙。资源牌尺寸与公开数量堆高规则保持独立。

舞台模式使用深蓝、细金线和玫瑰色徽记的 Loveca 牌背，覆盖双方可见牌背和移动中的牌背；二维桌面继续使用原牌背。卡图、权威数据与隐藏信息投影未改变。

中央列距收紧、卡面放大，手牌扇移到近景并增加尺寸；悬停时单张抬起以展示完整卡面。场区加入沿真实槽位铺设的深色嵌板，材质为细颗粒复合地面；收拢桌沿、补充纵向灯架及音箱单元的几何层次。成功 LIVE 继续沿世界纵深纵列排列。能量卡尺寸、对局控制位置和中央不显示文字的既定要求保持。

相机与 DOM 锚点共用 16:9 构图宽度上限，宽而矮的窗口按高度限制卡牌放大；窄窗资源区向桌内收拢。相机近平面调整到 1 世界单位，消除远机位下薄卡面与卡体之间的深度冲突。此轮没有引入新演出时序或规则命令；后续世界布局归一、舞台资产精细度与跨 GPU 性能仍需继续完成。

验收使用既有本地内存局面与真实 `GameBoard`，没有操作生产账号。几何、列距、拖动、区域投影、HUD、VFX、门禁及 Three 实体生命周期共 51 项 focused tests 通过；客户端 `tsc -b`、`vite build` 和 `git diff --check` 通过。舞台包为 946.21 kB / gzip 260.21 kB，保留原有大包提示。浏览器完成手牌拖入空槽、双击横置、非法对手落点回退、普通与专属登场终点、二维往返释放、双方视角的匿名牌背、0/1/5/12/20/60 张卡堆及减少动态检查；1728 × 974、1728 × 874、1280 × 720、850 × 898 检查构图，390 × 844 验证自动降级。证据位于仓库外 `animation-prototypes/concert-stage-20261004/output/concept-revision/`，以 `final-wide.png`、`final-card-detail.png`、`final-short.png`、`final-narrow.png` 为本轮最终样板；未进行跨 GPU 或正式联机验收。

## 卡面质感分步调整

首轮仅调整卡面反射与自发光，用户反馈卡面像蒙灰、立体感提升不明显，已撤回全部材质参数修改。后续优先处理静止画面可辨认的边缘截面与明暗层次，卡图保留原有表现；按用户要求逐项修改并交由用户视觉验收，不加入持续扫光或空闲绘制。

用户反馈第二轮窄边截面仍不明显，转向概念图中高于卡面的彩色边框：保留内沿、向内斜面、亮边和外倒角四段真实截面，顶边高度为短边的 2.8%、外沿宽度为 3.2%，由淡金渐变到浅蓝和淡紫，降低金属比例以保留可见色彩。底板按相同外扩量增加圆角半径，并整体收进边框轮廓内，消除四角露出的底板；叠放间距同时计入凸起边框，避免穿插。印刷面材质、图幅及卡纸厚度保持原值。

手牌常驻状态使用 DOM，因此同步调整手牌的彩色边框、外亮内暗的倒角阴影和嵌套圆角，拿起后衔接共享三维卡牌。新圆角只作用于三维舞台的手牌，二维桌面不变。本轮仅做相关几何测试和类型检查，视觉效果交由用户验收；未加入持续动画或空闲绘制。

用户随后反馈外框四角仍显多余、与概念图质感不符，此视觉版本尚未确认。手牌还叠加了独立 12px 圆角的蓝色效果提示框，与新边框及卡图自带轮廓未统一。按用户要求，先通过原有 `VITE_CARD_EFFECT_VISUAL_MARKERS` 开关将自动化覆盖标记改为默认关闭：蓝色边框、顶部圆点及三维对应轮廓一起关闭；构建时显式设置 `true`／`1`／`on` 可临时恢复。此开关不影响独立的紫色起动能力提示、绿色选牌提示或卡效执行。先由用户观察关闭后的卡牌轮廓，再确定实体边框的下一步调整。

用户已确认关闭蓝色标记后四角无多余部分。随后保持外轮廓、圆角、总宽度和高度，只拓宽三维边框的浅亮顶面、加强内壁明暗，顶面以珍珠暖白为主，淡金、浅蓝与淡紫集中在斜面。手牌用同样的宽亮顶面与较暗内壁，内壁占用既有边框宽度，仅在卡图边缘留轻微内阴影。印刷面材质与中部颜色不变。2026-10-06 用户反馈立体感仍无根本提升，按要求保存当前阶段版本并暂停调整；四角问题已确认解决，卡牌质感仍未达到概念图目标，不记为视觉完成。

修复三维资源区域接管后的按钮命中：父区域的 `pointer-events: none` 只负责让出旧矩形，资源区按钮与菜单显式恢复 `pointer-events: auto`，使自由模式“抽 1 张”和“放回牌库顶”可接收点击。原有禁用条件和命令权限保持不变。

首版相关 11 个测试文件共 79 项通过，覆盖场景几何/命中/清理、模式策略、登场生命周期、公开反馈、拖放与真实双增益结算；当时客户端 TypeScript 和生产构建通过。首次构建的舞台独立包约 927 kB，gzip 254 kB，不代表当前修订后的包体。正常速度录制与一次性验收局面位于仓库外的工作区 `animation-prototypes/concert-stage-20261004/`，不属于运行时资产。
