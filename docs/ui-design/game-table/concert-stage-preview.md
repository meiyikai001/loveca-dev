# 三维舞台本地试作

> 文档类型：专题说明
> 当前状态：2026-10-04 卡牌空间连续性修订已接入；仅本地调试与对墙打显式启用，尚未作为正式联机桌面开放；本轮本地视觉与回归验收已完成
> 维护范围：舞台渲染、原桌面交互衔接、动效与降级边界

## 入口和范围

在支持 WebGL2、视口至少 768 × 640 的本地调试或对墙打页面，点击右上角「舞台试作 · 2D」切换；再次点击恢复原桌面。选择按地址与端口保存在当前浏览器，5173 与独立演示页不共享开关。尺寸或显卡条件不满足时保留入口并说明原因。`?stage3d=1` / `?stage3d=0` 可指定初始选择，但不能绕过模式、尺寸或 WebGL 检查。手机、只读回放、观战、远程调试及正式联机继续使用原桌面。5173 正常入口可通过「对战 → 双人调试 → 选择双方卡组 → 开始」后启用；登录后的在线对墙打使用远端会话，当前仍保留二维，开关说明如何进入本机试作。

舞台使用 Three.js 与 React Three Fiber：有厚度的地板、灯架、音箱、远端灯带、观众光点、实体卡牌与接触阴影共用一个透视相机。场上成员、LIVE、成功 LIVE、能量及卡堆进入三维场景；成员、LIVE 与成功 LIVE 槽框和合法落点提示也在同一场景中渲染。手牌常驻展示仍是二维 DOM 扇形，拖起后可由共享三维卡接管；卡牌详情、选择菜单、数值和阶段按钮保留原交互。三维模式把对局控制面板收成可展开入口，以留出对手手牌空间。

本轮以固定机位与可操作性为基础，使用程序生成的场景几何与材质。已有简化灯架、音箱和远端光点不代表已还原批准概念图：两翼装饰占比、侧面 LED 屏、近景应援棒组合，以及带头像的身份面板和统一阶段 HUD，均尚未完成对应重设计。手牌也尚未按概念图重新构图。角色三维模型、额外 LIVE 演出、音效、镜头切换、精细舞台资产和移动端三维适配不在本轮实现中；尚未完成跨 GPU 性能验收。

## 与现有桌面的关系

`GameBoard` 仍使用同一个 `PlayerArea`、store selector、玩家投影与命令路径。`Stage3dBoardHost` 只读取显式标记为场上表面的 DOM：已经允许展示的卡图、姿态、选中/能力提示和布局矩形。背面只采集卡背，渲染器不读取卡组内容、对手手牌或权威游戏状态。

DOM 仍提供区域中心的布局锚点；`geometry.ts` 统一产生卡牌和槽位的世界姿态、投影四边形及命中范围。场上牌尺寸不再从各自 DOM 包围矩形反算；成员和 LIVE 共用固定物理尺寸，横置仅改变明确的模型朝向。原 DOM 事件表面通过投影矩阵跟随实际卡面，拖放仍返回原 droppable ID，不能退回旧矩形接受场上落点。采样时同步撤销再恢复自己写入的矩阵，避免投影结果再次成为布局输入。

纹理确认加载后才隐藏对应 DOM 卡图，菜单与数值保留。纹理失败、卡牌离开场区、关闭舞台、切换布局及 WebGL context 丢失时释放投影与隐藏标记。显卡中断后显示原桌面和重试提示。

Three.js 场景通过动态 import 按需运行。普通桌面不创建 Canvas；现有 PWA 仍预缓存构建中的 JavaScript，不能据此保证非三维设备完全不下载场景包。

## 2026-10-04：卡牌空间连续性修订

本轮修复卡牌、空槽、拖动代理与落地实体分别计算形状造成的错位，复用原命令路径与公开表现事件，不重写规则或另建游戏状态。

- **统一尺寸与槽位。** `STAGE3D_CARD_WIDTH = 1.5`、`STAGE3D_CARD_ASPECT = 1.4`，成员/LIVE 本体尺寸为 1.5 × 2.1 世界单位，比空间连续性初版的 2.25 × 3.15 缩小三分之一。能量卡保留 0.675、牌库、休息室与成功 LIVE 保留 0.7425 的绝对世界宽度，以维持资源可读性；资源标签、卡面和数量分别占位。空槽、占用槽、卡牌、槽框和拖放命中使用同一槽位姿态；LIVE 与成功 LIVE 的横置由 `rotation = -90` 表达。槽框区分普通、推荐、当前落点和可选状态，不据颜色自行改变合法性。
- **共享实体卡。** `StageCardVisual` 供静态卡、拖牌、普通移牌和登场落牌共同使用，包含轻圆角、薄倒角边缘、可读的卡面底色及轻微受光高光。常规卡面处于局部 `z = 0`，实体顶部保持在卡面下方，避免共面闪烁；能力与选中描边跟随卡牌受力。公开卡图按 URL 共用带引用计数的纹理，静态和动效对象只释放各自几何/材质，纹理由最后一个使用者释放。固定雾距离已改为相对相机距离，避免窄高窗口额外压暗卡面。
- **连续拖动和移牌。** `StageDragLayer` 在同一相机内显示抬起的共享卡，提前预热当前玩家已经可见的手牌纹理，起拖直接使用三维卡，关闭原二维拖动预览；松手姿态交给后续普通移牌或登场落牌。dnd-kit 在 onDragStart 之后才填入 active.rect，首帧使用当前可见卡的 DOM 锚点并固定拖动原点；快速松手也保留世界姿态。专属人物资产冷加载前先认领该姿态，避免加载时间超过短期交接窗口。涉及场区的普通 `CARD_MOVE` 在三维场景内插值位置、尺寸和朝向，终点使用目标世界姿态；交接检查静态卡纹理就绪及终点姿态，附带有界清理，避免遗留代理。取消、拒绝、无实际移动、视口变化和关闭舞台均释放临时表现。减少动态或三维链路不可用时仍沿用原表现降级。

这次修订没有重做周边装饰或身份/阶段 HUD，也没有把常驻手牌改成三维；原有登场人物段、HEART/BLADE 语义与规则结算保持共享。

本轮已在真实共用桌面验证 1600 × 1000 与当前内嵌窗口 850 × 898，按实际截图时间戳记录普通替换出牌、拖动与专属登场；鼠标留在最终卡面时无旧 hover 抬升，终点与槽框一致。实际操作验证场牌回手、空槽再次落牌、非法对手落点回退、单击能力菜单、右键详情、减少动态、二维切换、显卡中断及恢复、390 × 844 自动降级、双方视角下对手手牌仍为卡背。13 个相关单元/集成测试文件共 108 项通过，客户端 TypeScript 与生产构建通过（舞台独立包 932.05 kB / gzip 255.86 kB，仍有大包警告）。证据在仓库外 `animation-prototypes/concert-stage-20261004/output/card-space-revision/`：`landing-continuous.gif`、`drag-continuous.gif` 为正常速度实录，`wide-settled.png`、`narrow-final.png` 为真实桌面。尚未完成正式联机和跨 GPU 性能验收。下方 79 项仅为首版历史基线。

## 卡牌尺寸与资源排布验收

成员/LIVE 线性尺寸缩小三分之一，横置牌、空槽、拖牌和落牌终点继续共用世界尺寸；资源维持原有可读大小。资源区按窗口宽度三列或两列排布，标签、卡面、计数各自占位，能量横置后也预留对应宽度；成功 LIVE 三槽在三维模式横排，避免与对手能量区争用同一竖向空间。窄窗口外侧区域向内避开灯架。

本次实际检查 1600 × 1000、1280 × 720、850 × 898，验证成员/LIVE 间隔、资源标题与数量、能量全待横置及专属登场缩小后的终点。13 个相关测试文件共 109 项通过，客户端 TypeScript 与生产构建通过（舞台独立包 932.16 kB / gzip 255.88 kB，仍有大包警告）。按用户要求，本次不录制视频。补查实际开发入口的 StrictMode 后，修复卡牌和槽框资源在 effect 检查中被销毁后复用的问题；每次挂载重新创建并交接实体，周期采样重新同步 DOM 隐藏与投影命中，同值布局也能在投影释放后恢复。新增真实 Three 资源生命周期检查通过。用户截图的特定重影瞬间未完整复现，已针对实际发现的双层交接缺口修复。舞台提供完整的深色表面与文字变量，浅色应用主题下的卡效正文、关键词和按钮已实测可读。周边装饰和 HUD 在这次尺寸修复提交后继续开发。

普通无专属演出的登场与拖放移牌不再额外叠加高度弧线：从实际起点高度连续收敛到桌面，已在桌面高度的卡保持等高移动，避免松手后再次弹起。补充逐帧高度单调性与等高移动回归。

检视区与结算弹窗的拖牌保留在弹窗前方的 DOM 覆盖层，松手时把实际可见矩形交给三维移牌；场上和手牌原有三维拖动不变。实际将检视卡拖入手牌成功，拖动时采样确认层级为 1200；补充弹窗来源与交接尺寸回归。被压成员/能量的二维底色和描边仅在对应三维纹理就绪后隐藏，保持原命中表面与降级；实体层间距大于卡体厚度，避免穿插。成员上方不再出现不透明底框，M× 数量按钮可检视被压卡；补充 1、2、7、25 层顺序回归并实际检查单卡堆叠和详情打开。

## 动效语义

人物登场段沿用现有制作资产和共用时间轴。三维落牌接在原来的飞行/下压时段，保留 400 ms 飞行、150 ms 下压及整段约 2.74 s 的节奏、ACK、跳过、超时和默认位移动画抑制。卡牌落地触发短地面波纹，邻牌围绕接触边抬起，倾角随距离衰减，再回到原姿态。

HEART / BLADE 反馈消费既有已应用的公开反馈事件；数值和颜色来自真实结果。两类同时获得时同时展示，各种 HEART 颜色分别表现；支付费用不触发获得庆祝。同目标新反馈替换旧反馈，减少动态偏好保留更轻的提示。表现不阻塞命令或更改结算。

`stageVfxRuntime` 只连接共享表现事件与当前场景，负责句柄取消和退出清理。无舞台时继续走原二维表现。没有引入新的游戏事件协议、持久字段、独立规则引擎或隐藏信息访问。

## 首版验证基线（卡牌空间修订前）

使用与正式桌面相同的 `GameBoard` / `PlayerArea` 和内存 `GameSession`，以权威卡牌导出准备局面，演示动作提交真实命令。桌面验证覆盖 1600 × 900、1280 × 720，并补充 850 × 898 的实际内嵌窗口；手机 390 × 844、844 × 390 验证自动降级。实际操作覆盖手牌拖到成员槽、双击横置、卡牌详情、双方视角、阶段推进、2D/3D 切换、跳过演出、尺寸变化后的释放、模拟显卡中断与重试。
